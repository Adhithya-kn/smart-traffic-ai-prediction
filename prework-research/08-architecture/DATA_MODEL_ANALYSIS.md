## 1. Primary Dataset Schema & Entity Definitions

The core telemetry table encapsulates **203,906 observations** with 12 primary attributes representing continuous network flow, spatial topology, predictive modeling outcomes, and simulation interventions:

| Field Name | Data Type | Nullable | Example Value | Description & Engineering Significance |
| :--- | :---: | :---: | :--- | :--- |
| **`record_id`** | String (PK) | No | `REC_0104041` | Unique surrogate key identifying the observation instance. |
| **`road_id`** | String (FK) | No | `RD_100` | Identifier for the physical road segment (94 unique corridors). |
| **`intersection_id`**| String (FK) | No | `INT_052` | Closest connected intersection node (100 unique junctions). |
| **`city_zone`** | String | No | `Downtown Core` | Functional urban archetype (6 distinct metropolitan zones). |
| **`timestamp`** | Datetime | No | `2026-01-01 00:00:00` | Chronological timestamp of sensor telemetry capture. |
| **`vehicle_count`** | Integer | No | `151` | Instantaneous volume count of vehicles traversing the segment. |
| **`average_speed`** | Float | No | `40.0` | Space-mean speed (km/h) recorded across the observation window. |
| **`congestion_level`**| String (Enum)| No | `Low` | Observed ground-truth state at time $t$ (`Low`, `Moderate`, `High`, `Severe`). |
| **`Future_Congestion`**| String (Enum)| No | `Low` | Observed forward-horizon ground truth state at time $t+1$ on `road_id`. |
| **`Predicted_Future_Congestion`**| String (Enum)| No | `Low` | Model-inferred classification for time $t+1$ generated by XGBoost. |
| **`Simulated_Congestion_After_Action`**| String (Enum)| No | `Low` | Re-inferred state under counterfactual policy ($\alpha=0.20, \beta=0.10$). |
| **`Recommended_Action`**| String | No | `Continue regular...` | Municipal operational directive dispatched by Decision Engine. |
